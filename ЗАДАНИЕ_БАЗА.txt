В проекте 10 моделей — каждая соответствует одной таблице в базе данных.
Смотреть: catalog/models.py

  Справочники (неизменяемые данные):
    Role          — роли пользователей (Администратор, Менеджер и т.д.)
    Tag           — теги для протезов (лёгкий, водонепроницаемый и т.д.)
    ProsthesisType — типы протезов (протез руки, ноги, экзоскелет)
    RequestStatus — статусы заявок (Новая, В обработке, Одобрена)

  Основные объекты:
    User          — пользователи системы
    UserRole      — кто какие роли имеет (+ дата назначения)
    Prosthesis    — протезы в каталоге
    Request       — заявки от клиентов или инвесторов
    BlogPost      — статьи в блоге
    Event         — мероприятия и семинары
    Document      — сертификаты и лицензии

  __str__ — зачем нужен
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Без __str__ объект выглядит как «Prosthesis object (5)» — бессмысленно.
С __str__ Django показывает осмысленное название везде:
  — в выпадающих списках (select) в формах
  — в заголовках страниц администратора
  — в строковом представлении при отладке

Каждая модель в проекте имеет свой __str__:
  Role      → название роли
  User      → «Фамилия Имя (email)»
  Prosthesis → «Название (Тип протеза)»
  Request   → «Заявка №5 | На протез | Иванов»
  Document  → «Сертификат — Название документа»

Показать в админке: /admin/catalog/request/ — в каждой строке видна осмысленная подпись заявки.


━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━
  verbose_name — зачем нужен
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Без verbose_name Django показывает технические названия полей — «prosthesis_type», «is_active».
С verbose_name — «Тип протеза», «Активен».

Задаётся двумя способами:
  1. Для таблицы целиком — через class Meta:
       verbose_name        = 'Протез'
       verbose_name_plural = 'Протезы'
     Это меняет заголовки разделов в /admin/

  2. Для каждого поля отдельно:
       name = CharField(verbose_name='Название')
     Это меняет подписи в форме редактирования

Показать: /admin/catalog/prosthesis/add/ — все поля подписаны по-русски.
Разделы в /admin/ — «Протезы», «Заявки», а не «Prosthesis», «Request».

  Обязательность полей
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

В Django поле обязательное по умолчанию. Чтобы сделать необязательным —
нужно явно указать blank=True (для форм) и null=True (для базы данных).

Логика необязательных полей в проекте:

  User.phone — телефон можно не знать, необязателен
  Prosthesis.price — цена новинки может быть ещё не установлена
  Prosthesis.image — не у каждого протеза есть фото
  Request.user — заявки принимаются и без регистрации (гости)
  Request.prosthesis — заявки-инвесторов не привязаны к конкретному протезу
  Request.message — контактные данные обязательны, сообщение — нет
  BlogPost.published_at — черновик ещё не опубликован, даты нет
  Event.location — мероприятие может быть онлайн (без места)
  Event.website — сайт мероприятия может отсутствовать
  Document.file — технически необязателен, но по смыслу всегда заполняется

Показать: /admin/catalog/request/add/ — «Пользователь» и «Протез» не
помечены звёздочкой (необязательные), «Контакт» и «Статус» — помечены.

──────────────────────────────────────
  list_display — колонки в таблице
──────────────────────────────────────
По умолчанию Django показывает только одну колонку — __str__.
list_display позволяет вывести несколько полей сразу.

Показать: /admin/catalog/prosthesis/
Здесь видны колонки: ID, Название, Тип, Цена, Активен, Превью, Дата.
Превью — не поле модели, а метод, который возвращает HTML с <img>.


──────────────────────────────────────
  Собственный метод в list_display
──────────────────────────────────────
Иногда нужно показать данные, которых нет как отдельного поля:
миниатюру изображения, количество связанных объектов, цветной значок.

В проекте три примера:
  image_preview   — показывает превью фотографии протеза
  request_type_badge — цветной кружок с типом заявки
  prostheses_count — сколько протезов у данного типа

Показать: /admin/catalog/request/ — в колонке «Тип» цветные значки (синий / зелёный).


──────────────────────────────────────
  @admin.display и short_description
──────────────────────────────────────
Каждый метод в list_display нуждается в заголовке колонки.

Способ 1 — декоратор (современный, с Django 3.2):
  @admin.display(description='Превью')
  def image_preview(self, obj): ...

Способ 2 — прямой атрибут (классический, всегда работает):
  def users_count(self, obj): ...
  users_count.short_description = 'Кол-во пользователей'

Оба способа дают одинаковый результат — заголовок колонки в таблице.
В проекте используются оба: RoleAdmin использует прямой атрибут,
остальные — декоратор. Это сделано специально для демонстрации обоих.


──────────────────────────────────────
  list_filter — фильтры справа
──────────────────────────────────────
Боковая панель с фильтрами, которая позволяет быстро ограничивать список.
Django автоматически строит панель для BooleanField, CharField с choices,
DateField, ForeignKey.

Показать: /admin/catalog/prosthesis/ — справа «Активен», «Тип протеза», «Дата добавления».
Показать: /admin/catalog/user/ — фильтр «Роли» фильтрует по связанной таблице.


──────────────────────────────────────
  search_fields — полнотекстовый поиск
──────────────────────────────────────
Строка поиска над таблицей. Ищет по указанным полям через LIKE.
Можно искать по полям связанных таблиц — через двойное подчёркивание.

Показать: /admin/catalog/request/
Поиск по заявкам ищет одновременно:
  — в имени контакта (contact_name)
  — в сообщении (message)
  — в фамилии пользователя (user__last_name) — поле связанной таблицы!
  — в названии протеза (prosthesis__name)

Ввести в поиск фамилию пользователя — система найдёт его заявки.


──────────────────────────────────────
  inlines — вложенные объекты
──────────────────────────────────────
Позволяет редактировать связанные объекты прямо на странице родителя.
Например: открываем карточку пользователя — и сразу видим все его заявки,
статьи и роли, без перехода на отдельные страницы.

Показать: /admin/catalog/user/1/
Внизу страницы — четыре встроенные таблицы:
  Роли пользователя, Заявки пользователя, Статьи блога, Загруженные документы.


──────────────────────────────────────
  date_hierarchy — навигация по датам
──────────────────────────────────────
Появляется под таблицей и позволяет сужать список по году → месяцу → дню.
Удобно для анализа данных за период.

Показать: /admin/catalog/request/ — под таблицей навигация по датам создания заявок.
Кликнуть на год → откроются месяцы → кликнуть на месяц → дни.


──────────────────────────────────────
  filter_horizontal — виджет M2M
──────────────────────────────────────
Для поля ManyToMany по умолчанию Django рендерит <select multiple> — неудобно.
filter_horizontal заменяет его на два списка: «Доступно» и «Выбрано» со стрелками.

Показать: /admin/catalog/prosthesis/1/ — раздел «Теги».
Видны два поля с тегами, между ними стрелки для перемещения.


──────────────────────────────────────
  list_display_links — кликабельные колонки
──────────────────────────────────────
По умолчанию кликабельна только первая колонка (ведёт к форме редактирования).
list_display_links позволяет сделать кликабельными несколько колонок.

В проекте: list_display_links = ('id', 'name')
Показать: /admin/catalog/prosthesis/ — клик по ID или по названию открывает протез.


──────────────────────────────────────
  raw_id_fields — вместо большого select
──────────────────────────────────────
Проблема: если к заявке можно привязать протез, Django по умолчанию
загружает ВСЕ протезы в выпадающий список. При 1000+ записей страница
будет грузиться несколько секунд.

Решение: raw_id_fields показывает поле ввода для ID + кнопку-лупу.
Нажав лупу, открывается всплывающее окно с поиском — выбираем нужный объект.

Показать: /admin/catalog/request/add/ — поля «Пользователь» и «Протез»
имеют кнопку-лупу вместо выпадающего списка.


──────────────────────────────────────
  readonly_fields — поля только для чтения
──────────────────────────────────────
Некоторые поля не должны редактироваться вручную — например, дата создания
(ставится автоматически) или превью изображения (генерируется системой).

В проекте readonly_fields = ('id', 'created_at', 'image_preview')
Показать: /admin/catalog/prosthesis/1/ — поля ID, дата и превью отображаются
без виджета ввода — просто текст, который нельзя изменить.


──────────────────────────────────────
  LANGUAGE_CODE = 'ru'
──────────────────────────────────────
Настройка в config/settings.py (строка 113).
Переключает интерфейс Django-admin на русский язык:
кнопки «Сохранить», «Удалить», «Добавить», сообщения об ошибках — всё по-русски.

Показать: /admin/ — любая кнопка или форма — интерфейс на русском.
