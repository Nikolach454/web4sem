  ЗАДАНИЕ: models.ImageField
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Смотреть: catalog/models.py — поля image в Prosthesis, BlogPost, Event

ImageField — специальное поле для хранения изображений.
Технически является расширением FileField: сохраняет в MEDIA_ROOT,
а в базе данных хранит только ПУТЬ к файлу (строку), не сам файл.
Дополнительно проверяет что загружаемый файл является корректным изображением.

Требует установки библиотеки Pillow (указана в requirements.txt).
Без Pillow Django даже не запустится, если в моделях есть ImageField.

В проекте три модели с изображениями:
  Prosthesis.image — фотография протеза, preview в списке администратора
  BlogPost.image   — обложка статьи
  Event.image      — иллюстрация мероприятия

Как работает upload_to='prostheses/':
  Файл сохраняется по пути MEDIA_ROOT/prostheses/имя_файла.jpg
  То есть физически: папка media/prostheses/ в корне проекта.
  Если папки ещё нет — Django создаёт её автоматически.

Показать:
  /catalog/prostheses/create/ — поле «Изображение» в форме создания.
  Загрузить картинку → сохранить → в списке протезов появится превью.
  Физически файл появится в папке media/prostheses/ (проверить в файловой системе).

  ЗАДАНИЕ: models.FileField
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Смотреть: catalog/models.py — Document.file

FileField — поле для хранения любых файлов: PDF, Word, Excel, ZIP и т.д.
В отличие от ImageField не проверяет формат файла — принимает что угодно.
В базе данных также хранит только путь, сам файл — в файловой системе.

Показать:
  /admin/catalog/document/add/ — поле «Файл» принимает любой файл.
  После загрузки в списке /admin/catalog/document/ появляется ссылка «Открыть» →
  кликнуть — скачается загруженный файл.
  Файл физически сохранён в папке media/documents/.

Смотреть: catalog/views.py — в каждой view-функции создания/удаления

Зачем нужен редирект после успешной обработки формы:
  Когда форма отправляется (POST), сервер обрабатывает данные.
  Если просто отрисовать страницу — в браузере «висит» POST-запрос.
  Нажав F5, браузер ПОВТОРНО отправит форму → создастся дублирующийся объект.

  Паттерн «Post/Redirect/Get»:
    1. Пользователь заполняет форму (GET)
    2. Нажимает «Сохранить» (POST)
    3. Сервер сохраняет данные и отвечает РЕДИРЕКТОМ (301/302)
    4. Браузер переходит на новый URL (GET)
    5. Теперь F5 безопасен — перезапросит GET, а не POST

В проекте:
  Создание протеза → redirect на страницу созданного протеза
  Редактирование → redirect на страницу отредактированного протеза
  Удаление → redirect на список протезов

Показать: создать протез → после нажатия «Сохранить» URL в браузере
изменился на /catalog/prostheses/5/ — это и есть редирект.

  ЗАДАНИЕ: Генерация PDF в администраторе
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Смотреть: catalog/admin.py — функции export_requests_pdf, export_prostheses_pdf

Библиотека reportlab позволяет создавать PDF-документы программно.
Файл создаётся в оперативной памяти (без записи на диск) и сразу отдаётся браузеру.

Как работает:
  buffer = io.BytesIO()   — буфер в памяти вместо файла на диске
  canvas.Canvas(buffer)  — «холст» для рисования PDF
  Рисуем текст, таблицы → p.save() → отдаём buffer через FileResponse

Показать:
  1. Открыть /admin/catalog/request/
  2. Поставить галочки у нескольких заявок
  3. В выпадающем «Действие» выбрать «Сгенерировать PDF-отчёт по выбранным заявкам»
  4. Нажать «Выполнить» → браузер скачает requests_report.pdf

Аналогично для протезов: /admin/catalog/prosthesis/ → PDF-каталог.

  ЗАДАНИЕ: Добавить действие в администратор
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Смотреть: catalog/admin.py — функция mark_in_progress

Стандартное действие в Django admin — «Удалить выбранные объекты».
Можно добавлять собственные действия для массовых операций.

Действие mark_in_progress:
  Отмечаем несколько заявок → выбираем действие → все выбранные заявки
  получают новый статус. Это массовое обновление через один SQL UPDATE.

Показать:
  1. /admin/catalog/request/
  2. Отметить 2–3 заявки галочкой
  3. Выбрать «Пометить заявки как "В обработке"» → «Выполнить»
  4. Статус у выбранных заявок обновился

  ВОПРОС: Собственный функциональный метод в модели
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Смотреть: catalog/models.py — User.full_name, get_absolute_url в каждой модели

Метод модели — это обычный Python-метод, привязанный к объекту данных.
Он позволяет инкапсулировать бизнес-логику внутри модели,
а не разбрасывать её по views и шаблонам.

Пример 1 — вычисляемое свойство @property:
  User.full_name объединяет фамилию и имя в одну строку.
  @property означает: вызывается как атрибут (user.full_name), не как метод.
  Используется в admin.py и в шаблонах.

Пример 2 — get_absolute_url:
  Возвращает URL страницы объекта.
  Используется в views.py для редиректа после сохранения.
  Используется в шаблонах для ссылок.
  Используется в admin — Django автоматически добавляет кнопку «Просмотреть на сайте».

Разница @property и обычного метода:
  @property → obj.full_name            — без скобок, как атрибут
  обычный   → obj.get_absolute_url()   — со скобками, как функция

  ВОПРОС: File Uploads — особенности в формах
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Смотреть: catalog/templates/catalog/prosthesis_form.html и catalog/views.py

Особенность 1 — enctype в теге form:
  <form method="post" enctype="multipart/form-data">
  Без enctype="multipart/form-data" файл не будет передан на сервер вообще.
  Браузер отправит только текстовые поля, файл проигнорирует.
  Это стандарт HTTP — бинарные данные требуют другой кодировки.

Особенность 2 — request.FILES в view:
  При обычной форме: form = Form(request.POST)
  При форме с файлом: form = Form(request.POST, request.FILES)
  Файлы приходят в отдельном словаре request.FILES, не в request.POST.

Особенность 3 — настройки в settings.py:
  MEDIA_ROOT = BASE_DIR / 'media'  — куда физически сохранять файлы
  MEDIA_URL  = '/media/'           — с какого URL раздавать файлы

Особенность 4 — раздача файлов при разработке:
  В режиме DEBUG Django сам раздаёт медиафайлы через urls.py.
  В production так нельзя — Django медленно отдаёт статику.
  Там нужен nginx или S3-хранилище.

Особенность 5 — удаление файла:
  Когда объект удаляется из БД, физический файл НЕ удаляется автоматически.
  Нужно самостоятельно удалять файл в сигнале pre_delete или post_delete.
