1. ЦЕЛЬ САЙТА И ФУНКЦИОНАЛЬНЫЕ ВОЗМОЖНОСТИ ГЛАВНОЙ СТРАНИЦЫ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Сайт «ПротезМед» — информационный портал центра протезирования.
Основная цель: помочь людям с ампутациями и врождёнными
особенностями найти подходящий протез и оставить заявку
на консультацию.

Три функциональные задачи главной страницы:

  Задача 1. Просмотр каталога протезов по типам и новинок.
    Пользователь видит виджет «Новинки каталога» (последние
    добавленные активные протезы) и плитки с типами протезов,
    по каждой из которых указано количество изделий. Переход
    на страницу каталога с фильтром по выбранному типу.

  Задача 2. Чтение актуальных новостей и статей о протезировании.
    Виджет «Последние новости» отображает 4 последние
    опубликованные статьи блога с датой, автором и кратким
    содержанием. Кликабельный заголовок ведёт на полную статью.

  Задача 3. Знакомство с ближайшими мероприятиями центра.
    Виджет «Ближайшие мероприятия» показывает предстоящие события
    (фильтрация: event_date >= сегодня), сортированные по дате.
    Отображается дата, название, место проведения.

Дополнительно на главной:
  — поиск по каталогу протезов (требование 7),
  — счётчики-агрегаты: всего изделий, заявок, статей, средняя цена,
  — секция «Компенсация по госпрограмме» с CTA «Оставить заявку».

2. ВИДЖЕТЫ ГЛАВНОЙ СТРАНИЦЫ (catalog/templates/catalog/home.html)

Виджет 1 — «Протезы нашей фирмы» (по типам):
  Заголовок: «Протезы нашей фирмы»
  Содержимое: сетка плиток, каждая = тип протеза + счётчик (annotate).
  Ссылка: каждая плитка ведёт на каталог с фильтром ?type=<pk>.
  Ссылка «Весь каталог» в шапке виджета.

  тип (бейдж), цена или «по запросу».

  Содержимое: 4 последние опубликованные статьи.
  По каждой: кликабельный заголовок, автор, дата, фрагмент текста.

Виджет 4 — «Ближайшие мероприятия»:

  По каждому: дата-блок (число + месяц), название (кликабельно),

  Кнопка «Все мероприятия».

Виджет 5 — Счётчики-агрегаты (stats-bar):
  4 цветные плитки: всего изделий в каталоге (COUNT), заявок
  обработано (COUNT), статей в блоге (COUNT), средняя цена (AVG).

Главная страница (views.py, функция home) выводит данные
из 5 таблиц:

  5. Request (count)
     — счётчик «заявок обработано» в stats-bar

5. ПРИМЕРЫ QUERYSET (views.py, функция home + другие вьюхи)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Пример 1 — filter() + Q() + __icontains + select_related (поиск):
──────────────────────────────────────────────────────────────────
  search_results = (
      Prosthesis.active                              # кастомный менеджер: is_active=True
      .select_related('prosthesis_type')             # JOIN, без лишних запросов
      .filter(
          Q(name__icontains=search_query) |          # поиск по названию
          Q(description__icontains=search_query) |   # поиск по описанию
          Q(prosthesis_type__name__icontains=search_query)  # __ к связанной таблице
      )
      .order_by('name')
  )

  SQL-эквивалент (упрощённо):
    SELECT p.*, t.name AS type_name
    FROM catalog_prosthesis p
    JOIN catalog_prosthesistype t ON p.prosthesis_type_id = t.id
    WHERE p.is_active = 1
      AND (p.name LIKE '%запрос%'
           OR p.description LIKE '%запрос%'
           OR t.name LIKE '%запрос%')
    ORDER BY p.name;

──────────────────────────────────────────────────────────────────
Пример 2 — filter(is_published=True) + order_by('-published_at'):
──────────────────────────────────────────────────────────────────
  recent_posts = (
      BlogPost.objects
      .filter(is_published=True)     # только опубликованные статьи
      .select_related('author')      # JOIN с таблицей User
      .order_by('-published_at')     # сортировка: сначала новые
      [:4]                           # срез — не более 4
  )

  SQL-эквивалент:
    SELECT b.*, u.last_name, u.first_name
    FROM catalog_blogpost b
    LEFT JOIN catalog_user u ON b.author_id = u.id
    WHERE b.is_published = 1
    ORDER BY b.published_at DESC
    LIMIT 4;

──────────────────────────────────────────────────────────────────
Пример 3 — filter(event_date__gte=timezone.now()) + order_by:
──────────────────────────────────────────────────────────────────
  upcoming_events = (
      Event.objects
      .filter(event_date__gte=timezone.now())   # только будущие события
      .select_related('author')
      .order_by('event_date')                   # сортировка: ближайшее первым
      [:4]

    SELECT e.*, u.last_name
    FROM catalog_event e
    LEFT JOIN catalog_user u ON e.author_id = u.id
    WHERE e.event_date >= NOW()
    ORDER BY e.event_date ASC
    LIMIT 4;

6. АГРЕГАТНЫЕ ФУНКЦИИ (требование 6)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Агрегат 1 — aggregate() на главной странице (views.py, home):
  price_stats = Prosthesis.active.aggregate(
      total=Count('id'),        # COUNT — всего изделий в каталоге
      avg_price=Avg('price'),   # AVG  — средняя цена
      min_price=Min('price'),   # MIN  — минимальная цена
      max_price=Max('price'),   # MAX  — максимальная цена
  )

  SQL-эквивалент:
    SELECT COUNT(id), AVG(price), MIN(price), MAX(price)
    FROM catalog_prosthesis
    WHERE is_active = 1;

  Где используется: stats-bar на главной (плитки с цифрами).

Агрегат 2 — annotate() Count на главной странице:
  types_by_count = (
      ProsthesisType.objects
      .annotate(count=Count('prostheses'))   # COUNT для каждого типа
      .filter(count__gt=0)
      .order_by('-count')[:5]
  )

  SQL-эквивалент:
    SELECT t.*, COUNT(p.id) AS count
    FROM catalog_prosthesistype t
    LEFT JOIN catalog_prosthesis p ON p.prosthesis_type_id = t.id
    GROUP BY t.id
    HAVING count > 0
    ORDER BY count DESC
    LIMIT 5;

  Где используется: виджет «Протезы нашей фирмы» — счётчик (N шт.)
  на каждой плитке типа протеза.

Агрегат 3 — полная статистика (views.py, stats):
  price_stats = Prosthesis.objects.aggregate(
      avg_price=Avg('price'),
      max_price=Max('price'),
      min_price=Min('price'),
      total_price=Sum('price'),   # SUM — сумма всех цен
      total_count=Count('id'),
  )
  Страница: /catalog/stats/

7. ПОИСК (требование 7)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Расположение: hero-секция главной страницы.

Механизм:
  1. Пользователь вводит текст в поле «Найти протез…»
  2. Нажимает кнопку «Найти» (или Enter)
  3. Форма отправляет GET-запрос: /?q=<запрос>
  4. Вьюха home() читает request.GET.get('q')
  5. Если q не пустой — выполняется QuerySet с Q():
       Prosthesis.active.filter(
           Q(name__icontains=q) |
           Q(description__icontains=q) |
           Q(prosthesis_type__name__icontains=q)
       ).order_by('name')
  6. Результаты выводятся в блоке «Результаты: «<запрос>»»
     в виде таблицы с колонками: №, Название, Тип, Цена, Подробнее
  7. Кнопка «✕ Сбросить» возвращает на главную без параметра

Поиск ищет одновременно по:
  — названию протеза (name)
  — описанию (description)
  — типу протеза (prosthesis_type__name, JOIN)

Если ничего не найдено — показывается сообщение с ссылкой
на полный каталог.

Дополнительный поиск — страница каталога (/catalog/prostheses/):
  — поиск по названию и типу (?q=...)
  — фильтр по типу (?type=<id>)
  — исключение без цены (?hide_no_price=1)
  — сортировка (?sort=name|-name|price|-price|...)

8. ДЕТАЛЬНАЯ СТРАНИЦА ОБЪЕКТА — ПРОТЕЗ (требования лаб. 2)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

URL-структура:
  /catalog/prostheses/<pk>/        — детальная страница (re_path)
  /catalog/prostheses/create/      — создание нового
  /catalog/prostheses/<pk>/edit/   — редактирование
  /catalog/prostheses/<pk>/delete/ — удаление

Пример URL с ID «вшитым» в адрес:
  http://127.0.0.1:8000/catalog/prostheses/3/
  (3 — это ID протеза, аналог kinopoisk.ru/film/1309570/)

URL определён через re_path (регулярное выражение):
  re_path(r'^prostheses/(?P<pk>[0-9]+)/$', views.prosthesis_detail)
  (?P<pk>[0-9]+) — именованная группа: одна или более цифр → pk

Данные на детальной странице (из 2 таблиц):
  — Prosthesis: название, тип, цена, описание, теги, изображение,
    статус активности, дата добавления
  — ProsthesisType: название типа (select_related)
  — Request: все заявки на этот протез (related_name='requests')
    с полями: тип заявки, контакт, статус, дата

Переход с главной/каталога → детальная: через ссылки
{{ p.get_absolute_url }} (метод модели → reverse('catalog:prosthesis_detail', args=[self.pk]))

Навигация: в меню шапки сайта (base.html) есть пункты:
  Главная | Каталог | Заявки | Блог | Мероприятия | Документы | Статистика

Функционал CRUD (требования 5, 6, 7):

  СОЗДАНИЕ (требование 7):
    URL: /catalog/prostheses/create/
    Вьюха: prosthesis_create (views.py)
    Форма: ProsthesisForm (forms.py)
    При GET — пустая форма.
    При POST — form.is_valid() → form.save() → redirect на детальную.
    Поддерживает загрузку изображения (request.FILES).

  РЕДАКТИРОВАНИЕ (требование 5):
    URL: /catalog/prostheses/<pk>/edit/
    Вьюха: prosthesis_edit (views.py)
    При GET — форма, заполненная данными объекта (instance=prosthesis).
    При POST — form.save() → redirect на детальную страницу.
    Кнопка «✏ Редактировать» прямо на детальной странице.

  УДАЛЕНИЕ (требование 6):
    URL: /catalog/prostheses/<pk>/delete/
    Вьюха: prosthesis_delete (views.py)
    При GET — страница подтверждения (prosthesis_confirm_delete.html).
    При POST — prosthesis.delete() → redirect на список каталога.
    Кнопка «🗑 Удалить» прямо на детальной странице.

  Демонстрация (требование 8):
    На странице каталога (/catalog/prostheses/) рядом с каждым
    протезом есть кнопки «Редактировать» и «Удалить».
    После удаления страница перезагружается без удалённого объекта.
